# 聊天流转 (WatchYourStream)

## 简介

跨群话题流转插件。当**同一用户**在多个白名单聊天流（群聊/私聊）中发言时，插件自动提取目标流的最近对话上下文，调用LLM生成自然的接话内容，实现话题在不同聊天流之间的无缝延续。

主项目：[MaiBot](https://github.com/Mai-with-u/MaiBot)

## 工作原理

1. 插件监听所有白名单聊天流中的消息。
2. 收到消息后，检查消息用户是否在用户白名单中、是否包含过滤关键词。
3. 遍历其他白名单聊天流，对每个目标流：
   - 检查是否处于**冷却期**（防止频繁触发）。
   - 检查目标流最近N条消息中是否有**相同用户**的发言（可配置时间窗口）。
   - 若条件满足，获取目标流最近K条历史消息，加上当前消息，通过LLM生成一句接话。
4. 将生成的接话发送到目标聊天流，实现话题流转。

## 配置说明

WebUI 配置界面包含以下部分：

### 基础设置
- **插件开关**：全局启用/禁用。

### 聊天流白名单
- 只有列表中的聊天流会参与流转（来源和目标都必须在此列表中）。

### 用户白名单
- 启用后，列表中的用户消息不会触发流转。

### 关键词过滤
- 包含指定关键词的消息不会触发流转。

### LLM与历史设置
- **启用LLM**：是否使用AI生成回复。
- **历史消息数量**：每次获取多少条最近消息作为上下文（默认20）。
- **包含流转消息**：是否将已经转发过的消息也纳入历史（实验性）。
- **LLM提示词**：可自定义提示词，支持 `{history}`、`{current_message}`、`{source_user}` 占位符。

### 触发条件
- **要求相同用户近期发言**：开启后，目标流必须在最近消息中存在当前用户的发言才会触发。
- **检查消息数**：检查最近多少条消息。
- **时间窗口（秒）**：限制消息的新鲜度，0表示不限。
- **冷却时间（秒）**：同一个聊天流触发后需要等待多久才能再次触发，防止刷屏。

### 回复设置
- **包含回复消息**：是否将回复类型的消息也作为历史上下文的一部分。

## 使用场景

### 场景一：多群话题同步
用户同时在群A和群B讨论同一个话题，当用户在群A发言后，插件自动将群A的上下文和群B的历史结合，在群B生成自然接话，使两个群的讨论保持一致。

### 场景二：私聊与群聊联动
用户在私聊中向Bot提问，同时在某个群聊中也有类似讨论，插件可将私聊内容流转到群聊，实现跨渠道智能回复。

### 场景三：团队协作
团队成员在不同工作群中发言，插件帮助总结和衔接，减少信息孤岛。

## 注意

- 请确保 MaiBot 版本 ≥ 1.0.0-rc.4。
- 建议合理设置冷却时间和历史消息数量，避免过度触发或上下文过长。
- LLM 调用会消耗 token，请根据实际需求启用。
- 插件会为每个聊天流维护冷却锁，重启后锁会丢失（但不会影响功能，只是可能短期内重复触发）。
